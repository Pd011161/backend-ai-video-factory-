## 2. ตารางพารามิเตอร์ (ค่าที่รับได้จริง)

| Parameter | Veo 3.1 / 3.1 Fast | Veo 3.1 Lite |
|---|---|---|
| `aspectRatio` | `"16:9"` (default) · `"9:16"` | เหมือนกัน |
| `durationSeconds` | `"4"` · `"6"` · `"8"` | เหมือนกัน |
| `resolution` | `"720p"` (default) · `"1080p"` · `"4k"` | `"720p"` · `"1080p"` |
| `personGeneration` | `"allow_all"` (text-to-video/extension) · `"allow_adult"` (image-based) | เหมือนกัน |
| `seed` | มี — **ไม่การันตี determinism** แค่ช่วยให้ผลใกล้เคียงขึ้น | เหมือนกัน |

## 3. ⚠️ กับดักที่ชนงานเรา: 1080p/4K บังคับ 8 วินาที

> `durationSeconds`: `"4"`, `"6"`, `"8"` — **`8` required for 1080p/4k/reference images**

คลิป Omni ที่ระบบเรามีอยู่ยาว **~10 วินาที** จึงเรนเดอร์ซ้ำที่ 1080p ให้ยาวเท่าเดิมในคำสั่งเดียวไม่ได้ ต้องยอมสั้นลงหรือใช้ extension ต่อ (ดูข้อ 8)

## 5. ข้อจำกัดที่ต้องรู้

- **เก็บไฟล์บน server 2 วัน** แล้วลบ — ต้องดาวน์โหลดลง S3 เอง (โปรเจกต์นี้ทำอยู่แล้วผ่าน `_persist_media`)
- **24fps** ตายตัว
- **1 คลิปต่อ 1 request**
- latency ต่ำสุด 11 วินาที สูงสุด 6 นาทีช่วง peak

# โหมด Input

## 6. Text-to-video / Image-to-video
ส่ง `prompt` เดี่ยว หรือ `prompt` + `image` (เป็นเฟรมแรก) — โค้ดในโปรเจกต์นี้ส่งเป็น **top-level args ไม่ใช่ `GenerateVideosSource`** (shape หลังเป็นของ Vertex เท่านั้น ยิงเข้า Developer API แล้ว 400 "use case not supported")

## 7. Reference images (สูงสุด 3 รูป)
> "Up to three images to be used as style and content references"
ใช้ล็อกหน้าตา subject ให้คงเดิม — **ต้องใช้ `durationSeconds: 8`** เช่นเดียวกับ 1080p

## 8. Video extension — ต่อคลิปได้ แต่มีเงื่อนไขแรง
> "Extend videos that you previously generated with Veo by 7 seconds and up to 20 times"
- **เฉพาะคลิปที่ Veo สร้างเองเท่านั้น** — คลิปจาก Omni หรือจากกล้อง ต่อไม่ได้
- input สูงสุด 141 วินาที
- **extension ได้แค่ 720p** (`"720p" only for extension`)

## 9. First/Last frame interpolation
กำหนดเฟรมแรกและเฟรมสุดท้าย ให้ Veo เติมตรงกลาง — โปรเจกต์นี้มี `interpolation_model: veo-3.1-generate-preview` ตั้งไว้แล้วใน `config.yaml`

# Upscaling — สถานะจริง ณ ส.ค. 2026

## 10. ⚠️ มีจริง แต่ยังเรียกไม่ได้

Google ประกาศ **Veo upscaling** บน Vertex AI (เมษายน 2026) ความสามารถตรงกับโจทย์ "คงเนื้อหาเดิม เพิ่มแค่ความชัด" เป๊ะ:

> "enhance your videos up to 1080p and 4K, regardless of whether they were generated by Veo, another AI model, or a traditional camera"

**แต่ ณ วันที่เขียน:**
- **private preview ต้องขอ allowlist** — ยังไม่ public preview
- **ไม่มี model id / REST endpoint / พารามิเตอร์ในเอกสารสาธารณะเลย** (ค้น Vertex model reference แล้วไม่พบ operation ชื่อ upscale)
- ทีม Google ตอบในฟอรัมนักพัฒนาว่า: *"for Vertex AI-related issues or access requests, please contact your Google Cloud sales representative"* — ไม่ใช่ช่องทาง API ปกติ
- **Vertex เท่านั้น** ส่วนโปรเจกต์นี้ตั้ง `video_gen.provider: "gemini_api"`
- ราคาที่พบ ($0.05 ที่ 1080p / $0.50 ที่ 4K) มาจาก**คำพูดผู้ใช้ในฟอรัม ไม่ใช่เอกสารทางการ** — อย่าเอาไปคิดต้นทุน

**สรุปสำหรับการตัดสินใจ:** วันนี้ทำ "เอาคลิป Omni เดิมมาเพิ่มความชัด" ด้วย Google API ไม่ได้ ทางที่เหลือคือ (ก) ขยายด้วย ffmpeg ในเครื่อง — คงเนื้อหา 100% แต่ไม่ได้รายละเอียดใหม่ (ข) เรนเดอร์ใหม่ด้วย Veo ที่ 1080p — ได้รายละเอียดจริงแต่เนื้อหาเปลี่ยนและติดเพดาน 8 วินาที

## 11. ส่งวิดีโอเข้าโมเดลด้วย Files API (สำหรับ *วิเคราะห์* ไม่ใช่ upscale)
`client.files.upload(file="clip.mp4")` → poll จน `state.name == "ACTIVE"` → ส่งเป็น `{"type": "video", "uri": f.uri, "mime_type": f.mime_type}`
- รับ `video/mp4`, `mov`, `webm`, `avi`, `mpeg`, `wmv`, `3gpp` ฯลฯ
- ขนาด 20GB (paid) / 2GB (free) — แนะนำใช้เมื่อไฟล์ > 100MB
- โมเดล**อ่านที่ 1 เฟรม/วินาที** และเสียง 1Kbps — พอสำหรับ understanding/QC **ไม่พอสำหรับงานที่ต้องการรายละเอียดภาพ**

# API ย่อ (อ้างอิงเร็ว)

```python
from google import genai
from google.genai import types

client = genai.Client(api_key=GEMINI_API_KEY)      # Developer API — veo-3.1-* อยู่ที่นี่
op = client.models.generate_videos(
    model="veo-3.1-fast-generate-preview",
    prompt="...",
    image=types.Image(image_bytes=png, mime_type="image/png"),   # ตัวเลือก: เฟรมแรก
    config=types.GenerateVideosConfig(
        resolution="1080p",        # 720p | 1080p | 4k (4k ไม่มีใน lite)
        duration_seconds=8,        # ต้องเป็น 8 ถ้า 1080p/4k/reference images
        aspect_ratio="16:9",
        number_of_videos=1,
    ),
)
while not op.done:                  # long-running operation — ต้อง poll เอง
    time.sleep(8)
    op = client.operations.get(op)
result = op.response or op.result
```

ผลลัพธ์ที่ **ไม่มี** วิดีโอ ให้ดู `rai_media_filtered_reasons` — โปรเจกต์นี้มี `_veo_reasons()` / `_is_name_filter()` ห่อไว้แล้ว (ชื่อคนจริง/คนดังเป็น filter แบบ deterministic รีทรายไม่ช่วย ต้องแก้ prompt)

## หมายเหตุ integrate โปรเจกต์นี้
`generate_video()` ใน `app/services/gemini_client.py` เป็น Veo จริงและใช้งานได้ แต่เป็น **dead code** — `app/api/routes.py` มี `if True:` บังคับทุก render ไป Omni · `config.yaml` ตั้ง `resolution: "720p"` และ `model: veo-3.1-fast-generate-preview` ที่ไม่เคยถูกใช้ · ถ้าจะขึ้น 1080p จริงต้องแก้ `_normalized_concat()` ที่ **hardcode 1280×720** ด้วย ไม่งั้นขั้น merge บีบกลับหมด · `MediaAsset.width/height` มีคอลัมน์แต่ยังไม่เคยเขียนค่า — ที่ว่างสำหรับบันทึกขนาดจริง · `episode_gate.required_width/height` มีไว้ตรวจ 1080p แล้วแต่ `enabled: false`
